# ADR-001: Dynamic two-tool MCP proxy with API key

## Status

Accepted (operator decision Q7 = a, 2026-11-15)

## Context

The official New Relic MCP has 37 tools reachable with an API key, plus OAuth-only ones. Extension
tools are declared at build time, and CompozyOS validates their schema digests, so they cannot change
at runtime. OAuth logins expire every 24 hours, which suits unattended agents poorly. New Relic
annotates its tools with `readOnlyHint: true` (CompozyOS indexes all 37 as `risk: read` without an
override).

## Decision

Expose the official MCP through two static extension tools, `mcp_tools` and `mcp_call`, backed by an
in-repo MCP client that uses the bound API key. The exposed catalog is filtered at runtime to tools
that are annotated read-only, not destructive, and not OAuth-only, and that live in a region whose MCP
is available.

## Alternatives Considered

### Static mirror (one native tool per remote tool, generated at build)

- **Pros**: native names and schemas in the catalog; one call per use.
- **Cons**:
  - needs a release for every New Relic change;
  - the build needs a key;
  - free accounts see dead tools;
  - schema drift breaks digests.
- **Why rejected**: violates the "no dead tools" and "no release per change" goals.

### OAuth servers only (v0.1 status quo)

- **Cons**: 24 h re-login; the operator keeps the manual `newrelicapi` setup.
- **Why rejected**: the problem this spec solves.

## Consequences

- **Positive**:
  - every working remote tool is reachable;
  - new tools appear automatically;
  - small context footprint, because schemas are loaded on demand.
- **Negative**:
  - two calls the first time a tool is used;
  - remote tools are not individually visible in CompozyOS tool policy, which only sees the two proxy
    tools.
- **Risk**: remote annotation changes. The filter fails closed (tools disappear).
