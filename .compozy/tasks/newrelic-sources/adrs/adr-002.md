# ADR-002: Investigation layer — NerdGraph tools plus OAuth-only official MCP

## Status

Accepted (operator decision Q6 = a, 2026-11-14)

## Context

Agents woken by a source need tools to investigate. The official New Relic MCP
(`https://mcp.newrelic.com/mcp/`) is the richest option, but:

- With a User API key, OAuth-only tools are still listed and fail on call with
  `403: Tool 'natural_language_to_nrql_query' requires OAuth authentication and cannot be used with a New Relic API key`
  (reproduced 2026-11-14). The tool descriptor carries no marker that would allow filtering.
- The MCP requires a paid plan and an admin toggle. Free accounts cannot use it.
- CompozyOS 0.7.0 extension manifests cannot attach secret headers to an HTTP MCP server, cannot
  filter an MCP server's tools, and cannot toggle SDK tools at runtime.
  `MCPServerConfig` (`internal/extension/manifest.go:204-216`) has only plain `headers`; SDK tools
  are always `visibility = model` (`build_describe.go:255`).
- Plan or entitlement is not exposed in a way that can be read reliably; only a capability probe is
  trustworthy.

The operator's requirement: whoever installs must never pay tokens following a path their plan
cannot serve.

## Decision

1. Ship our own read-only investigation tools backed by NerdGraph with the User API key. They work on
   every plan, and only tools that work with an API key are registered.
2. Declare the official MCP only as OAuth servers (`newrelic`, `newrelic-eu`). CompozyOS exposes MCP
   tools only after OAuth sign-in and tool listing succeed, so free or disabled accounts never expose
   MCP tools. With OAuth, the OAuth-only tools work.
3. Provide a capability probe, the doctor (startup log line and an operator command), so the
   operator knows whether signing in is worthwhile.

## Alternatives Considered

### Alternative 1: Official MCP with an API key

- **Pros**: no OAuth step.
- **Cons**: exposes tools that 403 (token waste); the manifest cannot carry the secret header
  (a stdio `mcp-remote` wrapper would be needed); free plans get a dead server.
- **Why rejected**: violates the token-waste requirement.

### Alternative 2: Only our NerdGraph tools (Q6 = b)

- **Pros**: fully predictable.
- **Cons**: loses New Relic's AI tools (natural language to NRQL, trace search) for paid users.
- **Why rejected**: the operator chose both.

### Alternative 3: Only the OAuth MCP (Q6 = c)

- **Pros**: least code.
- **Cons**: free users get no investigation tools.
- **Why rejected**: the operator chose both.

## Consequences

### Positive

- Every visible tool works. Paid users get the full MCP after one login, and free users lose nothing.

### Negative

- Some overlap between our tools and the MCP's tools for paid users. Agents may pick either; both work.
- The doctor tool is model-visible (SDK limitation). Its description says it is for operators.

### Risks

- The New Relic OAuth client contract may not fit CompozyOS's OAuth flow. S4 verifies it; if it
  fails, the MCP servers are documented as unavailable and only the tools ship.
